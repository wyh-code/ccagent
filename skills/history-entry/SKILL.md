# 编写 HISTORY.md 条目

本项目每次代码改动都要在 `HISTORY.md` 里追加一条记录，而不是覆盖或删除历史条目。格式固定如下：

```
### <一句话标题，概括这次改动做了什么>

- 变更摘要：<改了哪些文件、每个文件具体做了什么、为什么这么设计；
  涉及模块依赖方向/循环导入等工程取舍也要写清楚原因>
- 验证步骤：（纯开发侧改动，例如构建、改名、重构，不涉及喂给 Agent 的对话）
  - 每一步都把要跑的命令包进一句自然语言描述里
- 试试这些 prompt：（涉及 Agent/REPL 行为的改动）
  - 用自然语言写出几条可以直接喂给 REPL 的测试输入，覆盖正常路径和边界情况
```

要点：

1. 版本号（`## 0.x.0` 一级标题）按"这次改动对应 code.py 里的哪个 sXX 阶段"来定，不是每次提交都加。
2. "验证步骤"和"试试这些 prompt"二选一或都写，取决于这次改动是否会影响 Agent 对话行为。
3. 自然语言 prompt 要写成用户会真的打进 REPL 的句子，例如"列出当前目录下的所有文件"，不要写成命令行参数或伪代码。
4. 新增/修改代码时保留原有注释；如果新注释和旧注释冲突，以最新的为准，删掉过时的那条。
5. 注释使用 JS/TS 术语描述实现的功能本身即可，不要出现"字典""列表"这类 Python 术语，也不要写"行为对齐 code.py"之类的对照式描述。
